> 2026-11-22 23:40　前端 `web/`　后端 `server/`　数据 `data/ashare.db`

## 1. 怎么跑（uv 管理，一键启动）

环境由 `pyproject.toml` + `uv.lock` 声明，**不再手动 pip install**。

```bash
# ① 一键启动（推荐）
start.bat              # Windows 双击；默认 8000，占用则自动顺延到 8020
start.bat 9000         # 指定端口
start.bat dev          # 后端热重载（改 server/ 立即生效）
./start.sh             # Git Bash / macOS / Linux 同款

# ② 手动启动（等价）
uv sync                        # 建立/同步 .venv（首次会装全部依赖）
uv run dash                    # 默认 127.0.0.1:8000
uv run dash --port 9000        # 换端口
uv run dash --reload           # 开发模式

# ③ 前端开发（热更新，仍可用）
cd web && pnpm dev             # http://127.0.0.1:5173，/api 代理到 8000

# 改完前端要重新构建，8000 端口才会更新
cd web && pnpm build
```

一键脚本做四件事：`uv sync` → 缺 dist 就 `pnpm build` → 找空闲端口 → 起服务并打开浏览器。

打开 **http://127.0.0.1:8000/** 即为完整页面。

> 依赖清单（`pyproject.toml`）：akshare 1.20.65 / pandas 3.1.1 / fastapi 0.165.0 / uvicorn 0.54.0 / pyyaml。
> 命令行入口 `dash` 由 `[project.scripts]` 注册，等价于 `python -m server.main`。

## 3. 核心口径（可复核，不是黑箱）

**市场温度**
```
温度 = 100 − 全指(000985)恐慌度 + clip(沪深300 当日涨跌, ±3)
恐慌度 = (RV20 五年分位 + QVIX 五年分位) / 2   # 无期权标的只用 RV
```
分档：<15 寒冷刺骨 / <30 寒冷 / <45 偏冷 / <55 中性 / <70 偏热 / <85 炎热 / ≥85 热浪滚滚

**策略建议**（优先级从上到下）
1. 成长恐慌 >75 且 红利 PE 分位 >90 → `减仓观望：两端都不便宜`
2. 成长恐慌 >75 且 红利恐慌 <45 → `防守：红利为主，成长只留底仓`
3. 成长恐慌 <30 且 成长 PE 分位 <50 → `进攻：成长优先`
4. 其余 → `均衡持有`

**舆情情绪分（由三层合成，权重写在代码里）**

| 层 | 含义 | 数据源 | 权重 | 刻度 |
|---|---|---|---|---|
| ① 人气股评价 | 市场对这些热门股的**多空判断**（不是涨跌） | 东财千股千评 `综合得分`（0–100，含资金/技术/情绪）取热度股均值 | 40% | 0–100 |
| ② 快讯多空 | 消息面整体偏多还是偏空 | 财联社快讯最近 20 条标题，关键词打分 | 35% | 0–100（50 为中性） |
| ③ 热股涨跌表现 | 热门股当天的**结果**（不是看法） | 上涨占比 ×1.5 + 平均涨跌幅 ×0.8 | 25% | 0–100 |

```
综合 = 0.40×评价 + 0.35×快讯 + 0.25×表现     （某项缺失时按剩余权重归一）
快讯分 = 50 + 50 × (正 − 负) / 总条数
```

**① 和 ③ 的区别很重要**：① 是「大家怎么说」，③ 是「实际怎么走」。两者背离时（评价高但涨得差）说明预期还没兑现，往往是分歧点。

> 关键词库目前 ~30 个正/负词（利好/回购/增持/中标… vs 减持/亏损/立案/退市…）。
> **会有误判**：例如「下调融资保证金比例以稳定股市」会被判成负向。所以快讯层只作方向参考，权重给到 35% 而不是 50%。

**分风格建议（成长 / 价值）**

```
成长分 = 0.40×(100 − PE分位) + 0.35×(100 − 恐慌分位) + 0.25×相对强弱分位
         PE/恐慌取 科创50 与 中证有色 均值；相对强弱 = 科创50/中证红利 比值的 5 年分位

价值分 = 0.40×利差分位 + 0.30×(100 − PE分位) + 0.30×(100 − 恐慌分位)
         利差 = 指数股息率(MA20) − 10Y国债，取 中证红利 与 红利低波 的均值分位
```

分档：≥65 加仓 / 50–65 持有 / 35–50 减仓 / <35 回避。
两风格分差 >8 时给出「偏成长 / 偏价值」的相对强弱提示。

**极端信号**：9 个指数中，PE 五年分位 >90 或 <10（估值高位/低位），或恐慌度 >85（恐慌高位）的个数。

## 3.5 指数走势页（`server/trend.py`）

顶部导航「指数走势」与首页平级，链接 `http://127.0.0.1:8000/#/trend`，筛选状态写入地址栏（可分享同一视图）。

**筛选维度**

| 维度 | 取值 | 说明 |
|---|---|---|
| 指数/个股 | 18 个，按类型分组 | 宽基/大盘 5、价值/红利 4、成长 4、周期 1、海外 2、**个股 2（中国电信 601728 / 中国移动 600941）** |
| 区间 | 近1月 / 近3月 / 近半年 / 近1年 / 近3年 / 近5年 / 全部 | 交易日 21 / 63 / 125 / 250 / 750 / 1250 / 全历史（2015 起，海外至 2004） |
| 粒度 | 日 / 周 / 月 / 半年 / 年 | 默认随区间自动选（≤3月→日，半年→周，5年/全部→月），可手动改 |
| 视图 | 指数点位 / 累积收益 | 指数点位=真实指数点位折线（左轴即点位）；累积收益=区间起点归零的收益曲线 |
| 第二 Y 轴（指标） | 按指数类型分配，最多 2 条折线 | 见下表。折线随时问变化，与指数线共用时间轴 |
| 分位参考线 | 近1年 250 / 近3年 750 / 近5年 1250 / 全部 | 只在指标轴上画 20%/50%/80% 三条横线（绿/黄/红），**不产生折线**。已删除「PE 历史分位」这个重复的指标 |
| 对比指数 | 任意其他指数 | 主图下方**独立成图**，两线均为真实点位、各自独立 Y 轴，与指标互不干扰 |

**指标分配规则（只给对该类型真正有效的指标）**

| 指数类型 | 指标（按推荐优先级） | 不给股息率的原因 |
|---|---|---|
| 宽基/大盘 | PE-TTM、股债性价比、成交额、恐慌度、20日波动 | 宽基股息率稳定且低，区分度弱 |
| 价值/红利 | 股息率、股息率−10Y国债、PE-TTM、20日波动 | —— 股息率是核心，排第一 |
| 成长 | PE-TTM、恐慌度、20日波动、相对沪深300 | 成长股几乎不分红，股息率无参考价值 |
| 周期 | PE-TTM、恐慌度、20日波动 | 周期盈利波动大，股息率不稳定 |
| 海外 | 20日波动、相对沪深300 | 无人民币估值口径数据 |
| 个股 | 相对沪深300（60日）、成交额、20日波动 | 库内个股无 PE / 股息率 / 恐慌度，故不给估值类指标；成交额已从元换算为亿元 |

指标可用性按库内实际数据判定：国证指数（深证成指/创业板指/创成长/深证综指）无 PE，只给成交额/波动/相对强弱；股息率仅有 000015/000922/930955/H30269 四个价值类。

**分位参考线**：把 20%/50%/80% 分位换算成**指标数值**画三条水平虚线（如近3年 PE 80% 分位 = 14.36 倍），与指标共用一根副轴，直接看出当前是贵还是便宜。颜色固定为 20%绿 / 50%黄 / 80%红，标签直接标在图上（`80% 14.36倍`）。只画线，**不画背景色带**。指标轴范围会自动包住折线和三条分位线，避免分位线被裁掉。

**对比指数**：在主图下方单独成图（`.chart-card` 第二块），两条线均为**真实点位**、各自独立 Y 轴，与主图的指标完全解耦——选对比不会清空 PE，选 PE 也不会影响对比。附区间涨跌与强弱差统计。

**区间统计**：区间涨跌、最大回撤、20日年化波动、上涨/下跌周期数、每个指标的当前值 + 在其分位窗口内的分位。

> 口径细节：周期标签取桶内**最后一个真实交易日**（不是 `2026-11-30` 这类虚拟月末），避免出现未来日期；科创50 等指数发布前用基点 1000 填充的占位行会被剔除。

## 4. 采集与缓存（页面不直连原始接口）

页面所有请求**只读数据库**，刷多少次都不会触发外部抓取，也就不会被限流。
外部数据只由「每日任务」写一次。

| 表 | 作用 |
|---|---|
| `web_sentiment` | 热度榜 + 百度热搜明细（按自然日） |
| `web_sentiment_meta` | 当日舆情聚合结果（情绪分/均值/上涨占比/采集时间/来源） |
| `web_daily_summary` | 日/周/月总结正文（JSON）+ `generated_at` |
| `web_daily_snapshot` | 每日温度、行情、舆情、结论快照 |

**每日任务**（一次跑完三步，幂等）：

```bash
uv run python scripts/daily_job.py          # 正常跑，舆情 10 分钟内不重复抓
uv run python scripts/daily_job.py --force  # 强制重抓舆情
# 或 HTTP：curl -X POST http://127.0.0.1:8000/api/daily_job
```

Windows 计划任务：每天 20:10 执行一次 `scripts/daily_job.py`（`schtasks` 见脚本头部注释）。

**缓存优先级**
- `/api/sentiment`：只读当日缓存；无则回退最近一份并标 `stale`
- `/api/summary`：只读当日总结；无则回退上一期并标 `stale` + `note`；完全没有返回 `pending`
- 采集接口（`/api/collect/sentiment`、`/api/collect/summary`、`/api/daily_job`）**页面不调用**，只给自动化用

## 5. 每日快照（用于日/周/月复盘）

点右上角「保存今日快照」→ 写入 `web_daily_snapshot`：

| 字段 | 含义 |
|---|---|
| trade_date | 交易日 |
| temperature / fear | 当日温度、恐慌度 |
| sh_pct / sz_pct / amount / vol_ratio / smallcap | 行情快照 |
| sentiment_score / hot_mean_pct | 舆情快照 |
| anomaly / advice / summary | 信号数与结论 |

页面「温度历史」折线读这张表；积累后可在 `Summary` 组件把 `period` 切到 周/月 看区间均值。

> 也可以改成每日收盘后自动跑一次：
> `curl -X POST http://127.0.0.1:8000/api/snapshot`

## 7. 已知限制

1. **东财 push2 限流**（本机 IP 常态）：人气榜会退到雪球讨论榜，此时热度榜无涨跌幅（显示 —），情绪分主要靠上涨占比 + 百度热搜样本。
2. **舆情按自然日缓存、行情按交易日**：周末/夜间会出现「舆情 11-23、行情 11-20」的日期差，属正常。
3. **总结每晚 20:00 生成**：当天未跑任务时，页面显示上一期并标「显示上一期」；从未跑过则显示待生成提示。
4. **温度历史需要每天保存**，首次使用只有 1 个点。
5. 前端单包约 1.7 MB（ECharts 全量 + antd 全量），未做按需引入，后续可换 `echarts/core` 减体积。
6. UI 用 **Ant Design 6**（ConfigProvider 中文主题色 #2563EB），Trend 页全量用 antd 组件；首页仍保留原生 class 样式。ECharts 轴名需 `grid.top ≥ 42`（主图 48 / 对比图 42），否则轴名会被卡片上沿裁切。
6. 页面无登录、无多用户，本机自用定位。
7. 原来的大折线图已从首页移除（组件 `web/src/components/WatchChart.jsx` 仍保留，需要时可在 App 里加回）。
8. **走势页数据起点 2015**（中证/国证接口最早只到 2015-01），所以「全部数据」≈ 11 年；只有 `.IXIC` 能到 2004。
9. 走势页第二 Y 轴最多 2 条指标折线；对比指数已独立成图，不占主图右轴。
10. `pe_pct`（PE 历史分位折线）已删除——分位只用三条横线表达，避免与「分位窗口」重复造成困惑。
11. 个股走 `px_stock_daily`（不复权收盘价），成交额除以 1e8 换算为亿元；左轴文案自动显示「股价（元）」而非「指数点位」。个股指标无分位线，页面自动隐藏「分位参考线」筛选行。
